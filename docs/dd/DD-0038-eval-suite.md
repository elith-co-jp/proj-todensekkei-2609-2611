# DD-0038: 評価を 1 コマンドで回し、基準値より悪くなれば止める

- 状態: レビュー中
- 作成日: 2026-11-21
- 関連文書: [DD-0032](DD-0032-synthetic-logic-validation.md)、[DD-0035](DD-0035-reading-procedure.md)、[DD-0037](DD-0037-ci-and-circuit-elements.md)

## 1. 目的

変更で精度が下がっていないかを、誰でも 1 コマンドで確かめられるようにする。

- 評価のスクリプトは `analysis/tools` に 20 本以上あり、入口がばらばらだった。
- 固定 30 枚の正解データは手元に無い（2026-11-21 確認）。最初の正解は 12 月中旬に届く顧客の 30 枚になる。
  それまでは、正解のわかっている合成回路・合成図面で測る。
- 受領図面はスキャン（TIF 由来）。きれいな合成図面では配線の読み取りが 100% になり、悪化に気づけない。

## 2. 変えたこと

- `analysis/tools/eval_suite.py`: 次の 3 つを順に回し、指標を 1 つの表（`summary.json`・`summary.md`）にまとめる。
  - logic（DD-0032）: シミュレーション・回路コードの往復・波及範囲の一致、誤りを入れた図面の検出、誤警報、見逃し
  - reading（DD-0035）: 成立条件・3 値の判定・順引きの一致、不明・欠落のときの誤った断定
  - drawings: 合成図面（PDF → 画像 → 配線の読み取り → 回路）の配線の再現率・適合率、回路の意味の一致。
    **きれいな図面**と、**スキャンに似せて劣化させた図面**（線の太さ・読み取りの粗さ・ぼけ・ノイズ）の両方
- `analysis/eval_baseline.json`: 規模（`quick` / `full`）ごとの基準値。悪くなった指標があれば終了コード 1。
  割合は 0.005 まで、件数（誤警報・見逃し・エラー）は 1 件でも増えれば悪化とする。`--write-baseline` で更新する。
- `--model`（YOLO の重み）で記号の検出も行い、`--enable-ocr` で文字の読み取りも測る（ultralytics・RapidOCR が要る）。
- `--gold` と `--pred`（アプリの書き出し ZIP）で、顧客の正解との比較（`eval_reading.py`）も同じ表に入れる。この指標は基準値に入れない。
- CI（DD-0037）で `--quick`（約 15 秒）を毎回回し、結果を成果物に残す。`make eval`・`make eval-quick`。
- スキャン風の劣化は `analysis/synthetic_circuits/scan.py` に移し、学習データの水増し（`synthetic_scan_data.py`）と共通にした。

## 3. 現在の基準値（full、2026-11-21）

結果の全体は [docs/evidence/eval-suite-20261121.md](../evidence/eval-suite-20261121.md)。

| 指標 | 値 |
|------|---:|
| 合成回路のシミュレーション・コード往復・波及範囲の一致 | 100% |
| 誤りを入れた図面の検出 | 81.8%（見逃しの多くは入力の接点。I/O 表が無いと照合先が無い。DD-0033） |
| 読解手順（成立条件・判定・順引き） | 100%、誤った断定 0 |
| きれいな合成図面: 配線の再現率 / 適合率 / 回路の一致 | 100% / 100% / 100% |
| **スキャン風の合成図面: 配線の再現率 / 適合率 / 回路の一致** | **76.7% / 94.8% / 27.5%** |

スキャン風の図面では配線の取りこぼしが目立ち、1 本でも落ちると回路の一致が崩れる。劣化は実物より強めの可能性があるが
（実図面の固定 30 枚では再現率 98.1%。DD-0024）、配線の読み取りを改善するときの物差しとして使う。
