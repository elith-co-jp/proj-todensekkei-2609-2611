# DD-0029: 図面を回路コードに置き換え、「もしも」と波及範囲を調べる

- 状態: レビュー中
- 作成日: 2026-11-18
- 関連文書: [DD-0009-circuit-simulation.md](DD-0009-circuit-simulation.md), [DD-0028-lcapy-skidl-interop.md](DD-0028-lcapy-skidl-interop.md), [DD-0027-synthetic-circuit-loop.md](DD-0027-synthetic-circuit-loop.md)

## 1. 目的

PDF で受け取った図面を、システムが回路として理解し再現できる形（コード）にし、「A を変えたらどうなるか」の
シミュレーションと、変更の影響が及ぶ範囲（波及範囲）を検討できるようにする。

## 2. 全体の流れと正本

```text
PDF ─(ページ画像)─> アノテーション（AI 推論 + エディタで確認）
                     記号・端子・配線 = 図面上の位置の正本（bundle.json）
                         │ build_circuit（DD-0009）
                         v
                     Circuit（ノード・素子・コイルと接点の対応）
                         │
     ┌───────────────────┼──────────────────────────┬─────────────────────┐
     v                   v                          v                     v
 回路コード（.py）   simulate（リレーの動作を   what_if / run_sequence   impact
 = 電気の正本        状態が落ち着くまで解く）  （もしも・操作の手順）    （波及範囲）
 書き換えて再実行                                                         
     │
     └─> SKiDL / KiCad・Lcapy・SPICE（DD-0028・DD-0009 の出力）
```

- **位置の正本はアノテーション、電気の正本は回路コード。** 回路コードの各素子は `source=(図面 ID, 記号 ref)` を持ち、
  エディタの記号に戻れる。
- **リレーの動作は自前のシミュレーション（simulate）が受け持つ。** DD-0028 で調べた通り、Lcapy・SKiDL はリレー
  （コイルの電圧で接点が開閉する）を表せない。Lcapy は 1 状態ずつの解の照合、SKiDL はネットリストの受け渡しに使う。

## 3. 回路コード（`services/circuit_code.py`）

```python
from services.circuit_code import CircuitCode

c = CircuitCode('ER21216')
# ---- 図面 ER21216（ID 1）
c.contact_b('S2', 'P', 'N001', device='STOP', source=(1, 'STOP'), label='STOP')
c.contact_a('S1', 'N001', 'N002', device='PB1', source=(1, 'PB1'), label='PB1')
c.contact_a('S3', 'N001', 'N002', device='X R100', source=(1, 'XA'), label='X R100')
c.coil('K1', 'N002', '0', device='X R100', source=(1, 'XC'), label='X R100')
c.load('H1', 'N003', '0', source=(1, 'L'), label='RL')
circuit = c.build()
```

- `to_python(circuit)` で書き出し、`from_python(code)` で読み戻す。読み戻した回路は元の回路と素子・コイル・入力・
  ノード・確認が必要な箇所まで一致し、シミュレーションの結果も一致する（テストで確認。合成図面 6 枚でも一致）。
- コードを書き換えて読み戻せば、図面に手を入れずに回路を変えられる（例: b 接点を a 接点に変えると止まり方が変わる）。
- `from_python` はコードを実行するため、手元のコード専用にし、API では受け取らない（書き出しの API だけ）。

## 4. もしも（`services/circuit_whatif.py`）

| 変更 | 指定 | 回路での扱い |
|------|------|--------------|
| 外部入力の切り替え | `inputs: {器具番号: bool}` | 入力の On/Off |
| リレー・入力を動かす / 動かなくする | `devices: {器具番号: bool}` | 器具の動作を固定（手で押し込む・コイルが動かない） |
| 接点の溶着 / 接触不良 | `contacts: [{project_id, symbol_ref, closed}]` | 接点の開閉を固定 |
| 断線 | `open: [{project_id, symbol_ref}]` | 接点は開のまま、コイルは励磁しない、負荷は動かない |
| 短絡 | `short: [{project_id, symbol_ref}]` | 接点は閉のまま、コイル・負荷は両端がつながる（電源の短絡は警告） |

- `what_if`: 今の状態（入力と励磁）から解いた結果と、変更を加えて解き直した結果を比べ、変わったリレー・負荷
  （表示灯・電磁弁など）・接点を返す。`simulate` に `forced_devices`・`forced_contacts` を足し、負荷の状態（`loads`）も返すようにした。
- `run_sequence`: 操作の手順（押す → 離す → 止める …）を、前の手順の励磁を引き継いで順に解く。故障を全手順にかけられる
  （例: 自己保持の接点が接触不良なら、押している間だけ動く）。

## 5. 波及範囲

- 母線（P・0）で区切った「段（ラダーの 1 行）」ごとに素子をまとめ、器具 X の接点がある段のコイル・負荷を X の影響先とする。
  影響先のリレーの接点から同じことを繰り返し、段数（何段目で影響するか）をつけて返す。反対向き（その機器のコイルの段に
  接点がある機器 = 動かしうる機器）も返す。
- 接点の開閉の組み合わせは見ないため「影響しうる」範囲（取りこぼさない側）になる。実際に変わるかは「もしも」で確かめる。
  合成図面 10 枚で、各入力を切り替えて実際に変わったリレー・負荷がすべて静的な波及範囲に入ることをテストで確かめた。

## 6. API と画面

| API | 内容 |
|-----|------|
| `POST /api/circuit/code` | 回路コード（.py）のダウンロード |
| `POST /api/circuit/what-if` | `{project_ids, inputs, energized, change}` → before / after / changes |
| `POST /api/circuit/sequence` | `{project_ids, steps: [{label, inputs}], change}` → 手順ごとの状態と変化 |
| `POST /api/circuit/impact` | `{project_ids, device}` → 影響しうるリレー・負荷（段数つき）、動かしうる機器 |

回路シミュレーションの画面に「もしも・波及範囲」の欄を足した。機器を選んで「波及範囲」「動作させたら」「動かなくなったら」を
押すと、今の状態からの変化と影響範囲が出て、負荷はエディタの記号へ移れる。回路コードもここからダウンロードできる。

## 7. 「図面を完全に理解する」までに残っていること

回路コードと「もしも」は、アノテーションが正しい範囲で正しい。完全に再現するために残っている主な点:

1. **読み取りの精度**: 記号・端子・配線の AI 推論の取りこぼし（DD-0024 など）。回路にできなかった箇所は「確認が必要な箇所」
   としてコードにも `c.note(...)` で残る。ここが 0 になるまでエディタで直すのが前提。
2. **シート間の参照**: `kind=sheet_ref`（行先札）の配線はまだ回路でつながない。図面をまたぐのは母線と同じ器具番号のリレーだけ。
3. **時間の要素**: タイマー（限時接点）、ラッチ・キープリレー、動作の順序（どちらが先に動くか）は表せない。今は状態が
   落ち着くまで解く静的なモデル。必要なら手順のシミュレーションに時間を足す。
4. **素子の種類**: ダイオードの向き、交流回路、カード（2B-2RSAM など）の中身、計器・変換器は抵抗かその他として扱う。
5. **器具番号の照合**: 接点とコイルは器具番号の文字で対応づける（OCR の O/0 などは吸収）。対応がつかない接点は外部入力になる。
