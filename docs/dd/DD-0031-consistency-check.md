# DD-0031: 複数の解析方法の結果の矛盾をチェックし、精査して解消する

- 状態: レビュー中
- 作成日: 2026-11-18
- 関連文書: [DD-0029](DD-0029-circuit-code-whatif-impact.md), [DD-0030](DD-0030-sheet-links.md), [DD-0028](DD-0028-lcapy-skidl-interop.md), [DD-0007](DD-0007-accuracy-improvement-real-drawings.md)（リレー表 #40 #44）

## 1. 目的

図面を回路として「完全に理解する」には、1 つの解析方法の結果を信じるのではなく、独立した方法の結果が
食い違わないことを確かめる必要がある。複数の方法の結果を突き合わせて矛盾を見つけ、矛盾ごとに根拠を調べ直し（精査）、
根拠がそろうものはその場で直し、直した後にもう一度チェックできるようにする。

## 2. 突き合わせる組み合わせ

| check | 方法 A | 方法 B | 矛盾の例 |
|-------|--------|--------|----------|
| relay_table | 図面の記号（アノテーション） | 図面下部のリレー表（構造解析で読んだ表） | 表の器具のコイルが無い、表の行列の位置に接点が無い、器具番号・a/b が表と違う、表に無い接点 |
| coil_sheet | 接点の枠の中のシート番号（コイルのあるシート） | 実際にコイルがある図面 | 指すシートにコイルが無い |
| wire_numbers | 配線のつながり（ノード） | 電線番号 | 同じ電線番号が別々のつながりに分かれる、1 つのつながりに電線番号が 2 つ |
| sheet_links | 行先札の組（DD-0030） | 両側の電線番号 | 組にした札の両側で電線番号が違う、組にならない札（DD-0032） |
| open_terminals | 記号の端子 | 配線 | 接点・コイル・負荷の 2 端子の片方だけ配線がある（段の途切れ。DD-0032） |
| solvers | 内蔵の回路計算 | ngspice・Lcapy（入っていれば） | 電圧の有無が方法で違う（電源の 9 割以上と 1 割以下で比べ、その間の浮いたノードは比べない） |
| impact | 静的な波及範囲 | もしも（入力を 1 つずつ ON） | 波及範囲の外で状態が変わる（組み方の不具合） |
| stability | シミュレーション | 接点の種類 | 自分の b 接点でコイルを切って発振する（a/b の読み違い） |

比べられないもの（構造解析の結果が無い、ngspice・Lcapy が無い、など）は「比べられない」と理由を出し、黙って一致にしない。

## 3. 精査と直し方

矛盾ごとに、調べたことを順に `review` に残し、結論を `proposal`（直し方）に書く。根拠がそろうときだけ `fix` を付ける。

| 矛盾 | 精査 | fix を付ける条件 |
|------|------|------------------|
| 接点の a/b が表と違う | 表の行列の窓で器具番号が一致する接点の数、記号が AI の検出か人の登録か | 窓の中で器具番号が一致する接点が 1 つ |
| 接点の器具番号が表と違う | 窓の中で最も近い接点のラベル（別の器具なら「位置に接点が無い」） | ラベルが空か 1 文字違い（シート番号は残す） |
| 表の器具のコイルが無い | 同じ図面のコイルのラベルとの 1 文字違い | 1 文字違いのコイルが 1 つ |
| 接点の指すシートにコイルが無い | 指す図面のコイルとの 1 文字違い、ほかの図面にあるか、ほかの接点・リレー表の器具番号 | 1 文字違いのコイルが 1 つで、ほかの接点・表も接点と同じ → コイルを直す。ほかの接点・表が無い → 接点を直す。ほかの 1 枚にだけコイルがある → シート番号を直す |
| 組にならない行先札 | 同じ電線番号でこちらの図面へ向かう札 | ほかの図面に 1 つだけ → 札のシート番号を直す |
| 自分の b 接点で発振 | コイルと同じ段にある自分の b 接点、リレー表の a/b | リレー表で a 接点か表に無い（要確認。まとめて直す対象にしない）。表でも b 接点なら余分な接続を疑い、直し方を出さない |
| 電線番号・行先札・回路計算・波及範囲 | 少ない側のつながり、多数決、範囲外のリレー | 付けない（人が図面で確かめる） |

- 同じ記号に同じ直し方を出した矛盾（例: リレー表と発振の両方が「a 接点にする」）は 1 つにまとめ、根拠を両方残す。
  同じ記号に違う直し方が出たら fix を外して人の判断に回す。
- 適用は記号の種類（a 接点・b 接点・コイル）とラベルだけ。変更は記号のメモに「整合性チェック（DD-0031）で 旧 → 新 に変更」
  と残す。適用の API はクライアントから直し方を受け取らず、選んだ矛盾の id でチェックし直し、いま出る直し方だけを使う。
- 画面の「矛盾をまとめて直す」は「矛盾」（2 つの方法の根拠がそろうもの）だけ。「要確認」は 1 件ずつ見て適用する。

## 4. 実装

| 追加・変更 | 内容 |
|------------|------|
| `services/consistency.py` | 8 組の突き合わせ（`Checker`）、精査、直し方のまとめ |
| `services/circuit_service.py` | `consistency_check`（構造解析の結果も読む）、`apply_consistency_fixes` |
| `POST /api/circuit/consistency` | `{project_ids}` → checks（組み合わせごとの結果）・issues・summary |
| `POST /api/circuit/consistency/apply` | `{project_ids, issue_ids}` → 適用した直し方と、もう一度チェックした結果 |
| 回路シミュレーション画面 | 「解析結果の整合性」: 組み合わせの表、矛盾ごとの精査の結果・直し方・エディタへのリンク・適用 |

## 5. テスト（`tests/test_consistency.py`）

- AI が自己保持の接点を b と読み違えた図面で、リレー表（a）と発振の両方が同じ直し方を出し、1 つにまとまる。
- 矛盾の無い図面では矛盾 0。
- 表の器具のコイルの 1 文字違いはラベルの直し方、表の位置に接点が無い・表に無い接点は要確認。
- 電線番号: 同じ番号が別のつながり（少ない側を示す）、1 つのつながりに 2 つの番号。
- 接点の指すシートにコイルが無く、その図面に 1 文字違いのコイルがあるとき、接点のラベルの直し方。
- Lcapy があるとき回路計算どうしが一致。API で適用すると記号が変わり、メモが残り、矛盾が消える。

## 6. 残っていること

- 構造解析（AI の配線・from-to）とアノテーションの配線の突き合わせ。人が直した結果との差は意図した変更も多いので、
  差を「矛盾」とせず、変更の履歴と合わせて扱う方法を決める。
- 「矛盾ではない」と人が判断した結果を残す（次のチェックで出さない）仕組み。
- 実図面（正解データの 30 図面）でチェックを流し、誤った指摘の割合を測って規則を調整する。
- 正解つきの合成回路での検証と、それで直した規則は [DD-0032](DD-0032-synthetic-logic-validation.md)。
