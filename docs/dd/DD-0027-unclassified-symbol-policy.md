# DD-0027 分類未合意の記号を暫定クラスで扱う

## 問題

Issue #42 のユニット、カード、装置、遮断器は、顧客と種類を合意していない。現行の注釈 API は未知のキーを新しいクラスとして登録し、推論と評価は同じキーを別々に扱う。この差は、未合意の種類を製品クラスとして確定したように見せる。

## 利用者から見た使い方

- 注釈に `card` または `breaker` が入っても、保存結果の `class_key` は `other` になる。
- 推論モデルまたは外部推論 ZIP が同じ名前を返しても、結果の `class_key` は `other` になる。
- `horizontal_contact_a` は `contact_a` として保存、表示、評価する。
- 顧客が種類を合意した後は、alias 表を外してクラスマスタと学習データを別の変更で更新する。

## 形

`symbol_class_policy.py` が alias 表と `canonical_symbol_class_key` を持つ。注釈、推論、固定図面の評価は、外部のクラス名を読む境界でこの関数を呼ぶ。未知のキーを自動登録する既存仕様は、Issue #42 に書かれた名前以外では保つ。

公開する関数は一つにする。alias 表はユニット、カード、装置、遮断器を `other` に写す。横向きを示す接頭辞または接尾辞は、元のキーが既存クラスにある場合だけ外す。

## 統合判断

alias 表を一か所に置く案を採用する。各経路に条件分岐を書く案は、追加時に経路間の差を再発させる。クラスマスタへ種類を追加する案は、顧客未合意の分類を確定するため採用しない。native subagent API がこのセッションに無いため、独立した cross-judge は実行していない。

## 受け入れる制約

- 種類別の精度は測らず、`other` 全体の検出精度だけを測る。
- `other_kind` は構造解析の暫定値として残すが、学習クラスにはしない。
- 横向きは新しいクラスにせず、既存クラスの回転例として扱う。

## 固定図面の評価

local GPU host にある固定正解 30 図面と、同じ 30 図面の保存済み fixed-weights 予測を branch の `holdout_cv.py --rescore` で 1 回再採点した。再採点は保存済み JSON に対する決定的な集計であり、試行間のばらつきはない。

| 対象 | 正解件数 | TP | FP | FN | 適合率 | 再現率 | F1 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 記号サイズの `other` | 174 | 173 | 4 | 1 | 0.9774 | 0.9943 | 0.9858 |
| 大枠の region 全体 | 74 | 72 | 2 | 2 | 0.9730 | 0.9730 | 0.9730 |
| 全記号 | 1,725 | 1,715 | 4 | 10 | 0.9977 | 0.9942 | 0.9959 |

固定正解には `other` が合計 248 件ある。ユニット、端子台ユニット、カード、装置、遮断器の独立した正解キーは 0 件で、横向き専用キーも 0 件だった。したがって種類別の適合率、再現率、F1 は算出できない。大枠の評価はクラスを分けないため、region の数値も種類別精度ではない。

## 比較した案

- 経路ごとの条件分岐は公開関数を増やさないが、同じ規則を三か所で同期する必要がある。
- クラスマスタへの追加は種類別評価を可能にするが、顧客合意前の製品分類になる。

## 未解決の点とリスク

- 合意後の種類別評価に必要な正解を、どの固定図面へ何件追加するか。
- 顧客合意後に、どの alias を独立クラスへ移すか。

## 実装結果

境界の挙動テストを先に失敗させ、共有関数を注釈、推論、評価へ追加した。一般の未知クラス自動登録は維持した。
