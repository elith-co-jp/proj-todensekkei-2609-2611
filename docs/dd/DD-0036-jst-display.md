# DD-0036: 画面・書き出しの時刻を日本時間にそろえる

- 状態: レビュー中
- 作成日: 2026-11-20
- 関連文書: [DATA_FORMAT.md](../DATA_FORMAT.md)

## 1. 目的

画面・API・書き出しファイルに出る時刻を、すべて日本時間（JST, UTC+9）にする。
これまでは DB の値（UTC）をそのまま返しており、学習の開始時刻やモデルの登録時刻が 9 時間ずれて見えていた。

## 2. 方針

- **保存は UTC のまま**（`models.utc_now_naive`、タイムゾーンなしの UTC）。DB の移行は不要で、既存データもそのまま正しく読める。
- **出すときに日本時間に直す**。`services/jst.py` の `iso_jst` で `+09:00` を付けた ISO 形式（例 `2026-11-20T17:10:05+09:00`）にする。
  オフセットが付くので、機械で読む側も時刻を取り違えない。
- 日本には夏時間がないので、固定の +9 時間（`timezone(timedelta(hours=9))`）を使う。Windows 版でも tzdata が要らない。
- 画面（フロントエンド）は `frontend/src/utils/jst.ts` で `Asia/Tokyo` を指定して表示する。PC のタイムゾーン設定に左右されない。
  オフセットのない古い形式の値は UTC とみなす。

## 3. 対象

| 箇所 | 以前 | 以後 |
|------|------|------|
| API の `created_at`・`updated_at`・`started_at`・`finished_at`・`undone_at`（図面・モデル・学習・図面の変更） | UTC、オフセットなし | 日本時間、`+09:00` |
| 学習・推論画面の時刻表示（モデルの登録時刻、学習の開始時刻） | UTC の文字列をそのまま表示 | 日本時間 |
| 書き出し画面のログの時刻 | PC のローカル時刻 | 日本時間 |
| ZIP 書き出しの `exported_at`、属性 JSON の `generated_at` | UTC（`+00:00`） | 日本時間（`+09:00`） |
| ダウンロードのファイル名の日時（`seqanno_export_YYYYMMDD_HHMMSS.zip` など） | UTC | 日本時間 |
| Docker のサーバー（ZIP 内のファイル日時など OS の時計を使う所） | UTC | `TZ=JST-9` で日本時間 |
| 解析 UI（`analysis/ui`）のジョブの時刻 | UTC | 日本時間（以前の UTC のジョブとも正しく並ぶ） |

DB に保存する値、学習・解析の経過秒数（`time.time()` の差）は対象外（時刻の表示ではないため）。

## 4. 検証

- `tests/test_jst.py`: UTC の値が `+09:00` の日本時間で出ること、日付をまたぐ場合、書き出し・ファイル名の時刻。
- `frontend/src/utils/jst.test.ts`: UTC で動くテスト環境でも日本時間で表示されること。
