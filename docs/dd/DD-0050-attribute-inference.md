# DD-0050: 図面の文字から属性を推定し、合成の図面文字で結び付けと推定を測る

- 状態: レビュー中
- 作成日: 2026-11-26
- 関連文書: [DD-0033](DD-0033-timers-and-reading-errors.md)（タイマー）・[DD-0045](DD-0045-logic-diagram.md)（論理図）・[DD-0046](DD-0046-drawing-logic-demo.md)（デモ）・[DD-0049](DD-0049-mark-only-boxes.md)（ラベルの結び付け）

## 1. 背景と決定

論理図とシミュレーションの動き方は記号の属性で決まる（タイマーの種類と時間、キープリレーのセット・リセット、信号名、外部入力）。
これまでは人が入れていた。紙芝居 EV31031〜EV31036 を調べると、どれも図面に文字で書かれているか、他盤との I/O 表で決まる。

- 図面の文字から推定できる 4 つを、AI 解析の候補として入れる（§2）。候補なので人が確かめる。決めきれなかったものは理由を残す。
- 図面だけでは決まらない「他盤から来る信号か」と「その名前」は、I/O 表を登録して入れる（§3）。
- 推定とラベルの結び付け（DD-0049）を、正解の分かる合成の図面文字（OCR の読み違いつき）で測り、改善の前後を比べる（§4・§5）。

検出（YOLO）の学習し直しは GPU と正解データが要るので、本 DD には入れない。

## 2. 属性の推定（`analysis/attribute_infer.py`）

| 属性 | 図面の書き方 | 推定 |
|---|---|---|
| `timer_mode`・`delay_s` | コイルの右に「1sec」と設定範囲「(0〜12sec)」、母線の下に型式「TDPU」 | 秒はコイルの中心より右から始まる文字（幅の 3 倍まで、上下は高さの 0.6 倍まで）。設定範囲は除く。種類はコイルの列（左右 1.5 個分）でコイルの下 2.5 個分までの型式（TDPU = オンディレー、TDDO = オフディレー）。型式が読めなければオンディレーとし、理由を残す |
| `latch_coil` | 並んだ 2 つの丸の中に「O」「R」、器具番号は 2 つの上に 1 つ | 丸の中（拡大の読み直しとページの文字）の O / S / SET = set、R / RESET = reset。印の読めたコイルを、同じ高さ（高さの 0.3 倍まで）で隙間が幅の 2.5 倍以下の隣のコイルと対にする（逆の印を優先、次に近い順）。片方だけ読めたら残りは逆とし、理由を残す。器具番号の無い方に対の器具番号を入れる。対にならないコイルの印は使わない（表示灯の印と区別できない） |
| `signal_name` | 母線の上に縦書きで回路の名前（「起動指令（個別制御装置）」） | 母線（電源母線端の記号か母線名 PEV110500 の行）より上の縦書き（高さが幅の 1.5 倍以上）の日本語を、列ごとにまとめる（括弧で始まる列は後ろ）。同じ縦の列の I/O の接点、無ければ最も近いコイルに入れる。いつも理由（読み違いを確かめる）を残す。結べなかった名前は `unlinked_captions` |
| `external_io` | I/O カードの接点「D001 B405」 | 器具番号が I/O の点番号（D + 3 桁）の接点 |

OCR の読み違い（実図面で確かめたもの）に合わせた: 「1sec」→「Isec」、「TDPU」→「TOPU」、I/O の番地の B → 8（`repair_io_label` で D### の次の 8### を B### に戻す）。

### 解析への組み込み

`extract_text_structure` の最後（ラベルを決め、日本語を読み直した後）で推定し、構造 JSON の記号に `attributes` と
`attribute_inference`（根拠の文字・位置・理由）を足す。キープリレーの対から入れたラベルは `label_link.status = 要確認`・`direction = pair`。
AI 取込（`services/ai_candidates.py`）は属性を記号に入れ、注記に「属性は図面の文字から推定（…）。要確認: …」と書く。
デモの AI 解析だけの図面（`_fill_from_ai`）も同じ属性を使う。

## 3. I/O 表（`services/io_table.py`）

- 形式: CSV（UTF-8 / Shift_JIS、カンマ・タブ区切り）か .xlsx の最初のシート。最初の 10 行から見出しを探し、器具番号の列
  （器具番号・I/O・点番号・信号番号・アドレス）、名前の列（信号名・名称・内容）、向きの列（任意。入出力・方向・種別。「出力」「DO」なら出力）を決める。
- 保存: `DATA_DIR/io_table.json`（1 つだけ。登録し直すと置き換える）。API は `GET / PUT / DELETE /api/circuit/io-table`、画面はデモの「I/O 表を登録」。
- 適用: 回路を組むたび（`circuit_service._pages`）に、器具番号（先頭 2 語の照合キー、参照先は除く）が一致する接点へ、入力の行は
  `external_io = yes` と `signal_name`、出力の行は `signal_name` だけ入れる。人が登録した図面では入っている属性を変えない。
  AI 解析だけの図面では、図面の文字から推定した値より I/O 表を優先する。DB の記号は書き換えない。

## 4. 合成の図面文字（`analysis/synthetic_circuits/sheet_text.py`）

紙芝居の展開接続図の書き方をまねて、1 枚ずつ文字（OCR の行と同じ形）・記号の枠・正解（ラベル・ラベルの位置・属性）を作る。

- 列の種類: I/O カードの接点（C / NO のピン名つき）、リレー（接点とコイル）、タイマー（「Xsec」「(0-Nsec)」型式）、キープリレー
  （O / R の対、器具番号は上に 1 つ）、並んだコイル。ラベルは右・上・下に書く（`label_side`）。端子番号・電線番号・参照先・母線の名前・縦書きの名前も置く。
- 読み違い（`noise` で強さを変える）: 行の抜け 4%、英数字の取り違え 6%（I/1・O/0・B/8・M/N など）、日本語の崩れ 35%、縦書きの分かれ、枠のずれ、Isec・TOPU。
- 配置の乱数と読み違いの乱数を分け、同じ seed ならノイズの強さを変えても配置は同じ。

評価（`analysis/tools/sheet_text_eval.py`）は解析と同じ順でラベルを決め（枠の中 → 結ぶ記号 → 近くの文字 → 属性の推定）、
ラベルは器具番号（先頭 2 語の照合キー）、ラベルの位置は IoU 0.3 以上、属性は種類ごとの適合率と再現率で比べる。

## 5. 結果

調整は seed 1〜999 で行い、測定は使っていない seed 50000〜50199（200 枚、記号 約 1 万個）で行った。
改善前は origin/main（dd0e0fb）の `label_link`・`text_extraction`。結果の JSON は [evidence/DD-0050-sheet-text-20261126.json](../evidence/DD-0050-sheet-text-20261126.json)。

| 読み違い | ラベルの当たり率 前 → 後 | ラベルの位置 前 → 後 |
|---|---|---|
| なし（0） | 0.832 → 0.997 | 0.976 → 0.983 |
| 中（0.5） | 0.771 → 0.941 | 0.955 → 0.969 |
| 強（1.0） | 0.720 → 0.889 | 0.932 → 0.950 |

| 属性（読み違い 中） | 適合率 | 再現率 |
|---|---|---|
| タイマー（種類と秒） | 0.985 | 0.985 |
| キープリレー | 0.988 | 0.983 |
| 信号名（正しい記号に付けたか） | 0.981 | 0.974 |
| 外部入力 | 1.000 | 0.963 |

改善前は属性の推定が無い（0）。ラベルの改善は合成データで見つけた次の誤りを直したもの:

- 枠の中に器具番号が読めた記号が外の文字を取り合っていた → 結ぶ記号（`targets`）だけが取り合う（枠はすべて文字を隠す）。
- 図面の枠の付け方の判断にコイル（丸の中に器具番号）を数えていた → 接点があれば接点だけで判断する。
- 数字の器具番号（3-52・80・52）を落としていた → まとまりに入れる。下に書いたラベルの前の端子番号は落とす。
- タイマーの注記・I/O カードのピン名（C・NO）・縦書きの電線番号がまとまりに入っていた → 入れない。
- 接点の棒「I」がくっついた語、B を 8 と読んだ I/O の番地、M / N の取り違え → 直す。

### 実図面で変わらないこと

- 今のモデルの検出 6 枚（紙芝居）・167 個のラベル: 変化 0。
- EV31036: 変化なし。EV31033 の実際の OCR（「TOPU」「Isec」）で on_delay・1 秒になることを確かめた。
- 実図面の縦書きの名前は OCR で崩れるので、信号名は日本語の読み直し（ローカル LLM）の後の文字に頼る。合成の値は実図面の当たり率ではない。

## 6. 戻し方

- 属性の推定を止める: `text_extraction._infer_attributes` の呼び出しを外す（構造 JSON から `attributes` が消え、AI 取込も入れない）。
- I/O 表: 画面の「I/O 表を外す」か `DELETE /api/circuit/io-table`。DB は書き換えないので、外すとすぐ元に戻る。
- ラベルの結び付けの変更は `label_link.py` の差分を戻す（DB・正解データには影響しない）。

## 7. 残り

- DGX の正解データ（30 枚）で、属性を人が入れたページと推定を突き合わせる。
- 実図面の縦書きの名前の読み直しの当たり率を測る（今は合成だけ）。
- I/O 表の実物（他盤の I/O 一覧）の列の名前を確かめ、見出しの候補を足す。
