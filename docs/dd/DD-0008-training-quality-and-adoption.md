# DD-0008: 学習データと採用判定の見える化（クラス別の評価・採用の基準・クラス別の件数・難例）

- 状態: レビュー中
- 作成日: 2026-11-06
- 関連文書: [DD-0006-customer-feedback-20261029.md](DD-0006-customer-feedback-20261029.md), [DD-0007-accuracy-improvement-real-drawings.md](DD-0007-accuracy-improvement-real-drawings.md), [SPECIFICATION.md](../SPECIFICATION.md)
- 関連 issue: #24

## 1. 背景

#24 は、アプリの改善サイクル（推論 → 人の修正 → 学習 → 採用判定）で精度を上げ続けるための作業を 5 分野に整理した。
評価基盤のうち、図面単位の評価用の分割（DD-0006）、確信度のしきい値の根拠（DD-0007 §4.13）、固定した評価用図面での回帰確認（DD-0007 §2 の `evaluate_all.py`）、図面向けのデータ拡張（DD-0007 §4.11）、検出後の解析の回帰評価（`eval_wiring_cv.py`・`eval_editor_import.py`）は対応済み。
残っていたのは次の 5 点で、本 DD で対応する。

| #24 の項目 | 状態（変更前） | 本 DD の対応 |
| --- | --- | --- |
| クラス別指標の記録 | 学習結果に全体の P・R・mAP だけを保存 | 評価用の図面でのクラス別の P・R・mAP50・mAP50-95 と件数を新旧モデルとも保存し、採用判定に表で出す |
| 採用判定の基準化 | 新旧の数値を並べるだけで、判断は利用者まかせ | 基準（§3）で「採用をおすすめ / 見送りをおすすめ / 判断できない」と理由を出す |
| クラス別アノテーション分布の可視化 | 一覧なし | 学習に使う図面（完了）のクラス別の正解件数と図面数を出し、30 件未満を「少ない」と示す |
| 難例の収集 | 一覧なし | AI の検出と直した後の正解の一致（種別も含めた F1）を完了の図面ごとに求め、低い順に並べる。0.9 未満を「難例」とする |
| ベースモデルの見直し | 使用中のモデルが無いときの学習の起点は yolov8n | yolo11s（DD-0007 §4.11 の交差検証で yolo11n より未学習図面の検出 F1 が高かった）。EXE に同梱する重みも差し替える |

「ネガティブ例の追加」は、記号の無い図面を完了にすれば空のラベルとして学習に入る（ultralytics は空のラベルの画像を背景として使う）ので、新しい仕組みは足さない。
「精度 KPI の記録」は、学習ジョブごとに全体とクラス別の値が残るようになったことで対応とする。

## 2. スコープ外

- 採用の自動化。基準は判断材料で、採用・見送りは従来どおり利用者が選ぶ。
- 難例の重み付け学習。難例の一覧は正解を見直す図面を選ぶためのもの。

## 3. 採用判定の基準

`services/training_service.adoption_review` で決める。

1. 新旧どちらかの全体の mAP50-95 が無ければ「自動では判定できません」。
2. 新モデルの全体の mAP50-95 が比較対象より 0.005 を超えて下がれば「見送りをおすすめ」。
3. 評価用の図面に 5 件以上あるクラスで、mAP50-95 が 0.05 を超えて下がれば「見送りをおすすめ」。5 件未満のクラスは 1 件で値が大きく動くため判定に使わない（DD-0007 §4.11 の b 接点は 13 件で F1 が 0.33〜0.53 の間で動いた）。
4. 2・3 に当たらなくても、学習に使った図面で評価したとき（評価用に分ける図面が 5 枚未満、または「未学習の図面で評価する」を外したとき）は「この評価だけでは判断できません」。
5. それ以外は「採用をおすすめ」。

## 4. 変更内容

- `services/training_service.py`: `_eval_weights` が ultralytics の val 結果からクラス別の値（`box.ap_class_index`・`p`・`r`・`ap50`・`ap`）を取り、評価用のラベルからクラス別の件数を数えて `metrics.per_class` に入れる。既存の `metrics_json` に入れるので DB の列は増やさない。`serialize_run` は `per_class`・`baseline_per_class`・`review` を分けて返し、`metrics` は従来どおり全体の値だけ。モデル一覧の `metrics` からもクラス別の値を外す。
- `services/training_data_service.py`（新規）: クラス別の件数（`GET /api/ml/training/class-stats`）と難例（`GET /api/ml/training/hard-drawings`）。難例は `review_service` の対応付け（枠の重なり 0.5 以上で 1 対 1）を使い、AI の検出は構造解析があれば取り込みの候補、無ければ推論結果。
- 画面（AI 改善サイクル）: 採用判定パネルに推奨と理由、クラス別の比較表。YOLO 学習のカードに「学習データの状態」（クラス別の件数、難例の図面とエディタへのリンク）。
- 学習の起点の重み: `DEFAULT_BASE_MODEL` を `yolo11s.pt` に、`scripts/fetch_base_model.py` と `seq-annotator.spec` を同じ重み（Ultralytics v8.3.0、SHA-256 `85a76fe86dd8afe384648546b56a7a78580c7cb7b404fc595f97969322d502d5`。DD-0007 の学習で使った重みと同じ）に変える。使用中のモデルがあるときは従来どおりそのモデルが起点。

| 確認内容 | 方法 | 結果 |

## 6. 残課題・判断事項

- 基準のしきい値（全体 0.005、クラス 0.05、5 件）は、DD-0007 の交差検証での値の揺れから決めた目安。運用での見直しが要る。
- 難例の一致は枠の重なりで数えるため、8〜15 px の黒丸は人が描いた枠の大きさで一致・不一致が決まることがある（DD-0007 §2）。
- 同梱の EXE を作り直すと、学習の起点の重みが約 6 MB から約 19 MB になる。

## 7. ロールバック

本 DD の差分を revert する。保存済みの `metrics_json` にクラス別の値が残っていても、従来の画面は全体の値だけを読む。
