# DD-0050: 表の読み取りを元の表と同じ並びで見せ、人が確かめて確定する

- 状態: レビュー中
- 作成日: 2026-11-27
- 関連文書: [DD-0031](DD-0031-consistency-check.md)（整合性チェック）、[DD-0047](DD-0047-explicit-state-machines.md)（状態の移り方）、[state-machines.md](../state-machines.md)

## 1. 背景

図面下部のリレー表・右下の表題欄は文字だけの表で、構造解析（`analysis/text_extraction.py`）が OCR で読み、リレー表は
「器具番号・端子・接点・シート・行列」の行（`relay_table.rows`）にして整合性チェックとシート間のリレーの照合に使っている。
OCR は小さな 1 文字（接点の A・B）をまとめて読み落としたり、「10D」を「1OD」、「器具番号」を「器具蛋号」と読んだりする。
これまで読み違いは整合性チェックの結果から間接的に見るしかなく、表として確かめて直す手段が無かった。

2026-11-27 の依頼: 表形式の文字の読み取りは、元の表に近い並びのまま OCR の結果を見せ、人が確かめ・直して確定できるようにする。

## 2. 表の格子（`analysis/table_grid.py`）

1. 表の範囲（`regions` の `relay_table`・`title_block`。文字から決めた範囲を優先し、無ければ検出した領域枠）に中心が入る文字を集める。
2. 行: 文字の中心の高さで分ける（文字の高さの中央値の 0.55 倍以内は同じ行）。
3. 列: 文字の左右の範囲を、重なるものどうしでつなぐ（隙間は足さない。隣の列との隙間が 2 px の表もある）。
   幅の中央値の 3 倍を超える文字（見出しが複数の列にまたがる）は列の幅を決めるのに使わず、`colspan` を付ける。
4. 罫線（`ruling_lines`。表の範囲の画像で文字の高さの 2.5 倍以上続く縦・横の線）があれば:
   - 罫線が文字の列の中を通れば列を分ける（「接点 シート」が 1 語に読まれても 2 列にする）。
   - 罫線で区切られ、横の罫線が横切る帯に文字の列が無ければ、空の列を作る（A・B をすべて読み落とした接点の列）。
     表と表の間の余白は横の罫線が横切らないので列にしない。行も同じ。
5. 器具番号の欄のように複数の行をまとめた欄の文字は行の間に書かれる。中心が隣の行から文字の高さの 0.9 倍未満で、
   その列が空いている行があれば、その行に入れる（文字だけの細い行を作らない）。
6. 同じ欄に入った複数の文字は左から空白でつなぎ、確からしさは一番低いものにする。

画面ではすべての行 × 列に入力欄を出す（文字の無い欄も直せる）。欄の境目は隣の行・列の文字の間の真ん中。

## 3. 確認と確定（`services/table_review.py`、`routers/tables.py`）

- `GET /api/projects/{id}/tables`: 表ごとに格子・今の値・状態（未確認／確認中／確定）・要確認（確からしさ 0.7 未満）の数・
  直した数、リレー表の行（`relay_rows`）とその出どころ（`relay_source`: `ocr` / `confirmed`）。
- `PUT /api/projects/{id}/tables/{kind}` `{values: [{row, col, text}], confirm}`: 直した値を保存する。`confirm` で確定、
  そうでなければ確認中（確定済みなら確定を解除）。
- `DELETE /api/projects/{id}/tables/{kind}`: 確かめた結果を消して、今の AI の読みから始め直す。
- DB: `table_reviews`（図面・表ごとに 1 行）。`grid_json` は確かめ始めたときの格子で、解析し直しても人が直した欄の位置はずれない。
  解析し直して AI の読みが変わったら `ocr_changed` を返し、画面で「最新の読みでやり直す」を出す。
- 状態: `TableReview.status` は `draft` ⇄ `confirmed`（`services/lifecycles.py` の `TableReviewLifecycle`）。

### 確定したリレー表を使う

確定すると、表の範囲の OCR の文字を人の値（元の文字の枠、書き足した欄は行・列の範囲）に置き換えて `parse_relay_table` を
回し直し、構造解析の結果の `relay_table.rows`・`links` に入れる。AI の読みは `ocr_rows`・`ocr_links` に残し、確定を解除・
やり直すと戻す。整合性チェック・シート間のリレーの照合・構造 JSON の書き出しは、そのまま人の読みを使う。
解析し直したとき（`save_structure`）も、確定したリレー表があれば保存の前に入れ直す。

表題欄は確定した値を保存するだけで、シート番号の候補などにはまだ使わない。

## 4. 画面（`#/projects/{id}/tables`、解析結果の「表の確認」）

- 表ごとのタブ（状態つき）。「上下」は図面の表（画像の切り出し）と読み取り結果を同じ倍率で上下に並べ、「重ねる」は図面の表の上に
  読みを右下に小さく重ねる。図面の表をクリックするとその欄へ移る。Enter・↓ で下の欄、Shift+Enter・↑ で上の欄。
- 欄の色: 要確認（黄）、直した欄（青）、AI が読んでいない欄（点線）。欄のツールチップに AI の読みと確からしさ。
- 「AI の読みに戻す」「下書き保存」「確定」。直した欄の一覧（AI の読み → 直した後）と、リレー表の行。

## 5. 確かめたこと

試験用に罫線つきのリレー表（2 列 × 2 段、器具 4 つ・16 行）と表題欄を描いた図面を RapidOCR で読んだ。AI の読みでは接点の A・B が
16 個すべて読めず、器具番号 33HB も読めなかった。格子は 10 行 × 10 列で、接点の列は罫線から空の列として出た。
33HB・接点を書き足して確定すると、リレー表の行の器具番号と接点が直った（`tests/test_table_review.py` は同じ流れを合成した文字で確かめる）。

## 6. 残り

- 罫線の無い表・斜めにスキャンした表は、文字の並びだけで格子を作る（読み落とした列は作れない）。
- I/O 表・端子表など、リレー表・表題欄以外の表の範囲は今は見つけない（`TABLE_KINDS` と範囲の決め方を足せば同じ画面で扱える）。
- 確定した表題欄をシート番号に使うこと、確定した読みを OCR の学習データにすること。
