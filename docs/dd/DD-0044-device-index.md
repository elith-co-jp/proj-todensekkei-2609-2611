# DD-0044: 機器索引（コイルと接点の相互参照・電線番号の一覧・Excel 出力）

- 状態: レビュー中
- 作成日: 2026-11-22
- 関連文書: [DD-0009](DD-0009-circuit-simulation.md)、[DD-0030](DD-0030-sheet-links.md)、[DD-0031](DD-0031-consistency-check.md)、[DD-0035](DD-0035-reading-procedure.md)、[DD-0041](DD-0041-drawing-sets.md)

## 1. 目的

展開接続図を読む人が毎日していることは、次の 3 つの「探す」作業が大半を占める。

- このリレー（器具番号）のコイルはどのページのどこにあり、その接点（a / b）はどのページのどこで使われているか。
  紙の図面では、コイルの下に接点の使用先（ページ・区画）を書く「接点展開表」を人が作って追う。
- この電線番号の線はどこからどこへ行くか。
- 読み取り（スキャンの OCR）の誤りで、同じ器具なのに別の器具として扱われていないか（「33HB」と「33H8」など）。

これまでの回路検証には、回路の動作・成立条件（条件タブ）・波及・整合性チェック（検査タブ）はあったが、
「器具番号で引いて、その器具が図面のどこにあるかを一覧で見て、そこへ飛ぶ」道具が無かった。回路の要約
（`/api/circuit/build`）はコイルと接点の対応を持つが、画面には器具番号と励磁の有無しか出ていなかった。
また、図面をまたいだ接点の使用先を表（Excel）で渡せなかった。

受領する図面はスキャンで正解が無く、各 PC の EXE で動かすため、追加の依存（外部サービス・LLM）は使わない。

## 2. 変えたこと

- `services/device_index.py`（DB を使わない）: 組んだ回路（`circuit_model.Circuit`）とアノテーションから、
  - **器具**: リレー（選んだ図面にコイルがある）・外部入力（コイルが無い接点）・負荷（表示灯・電磁弁など）ごとに、
    コイル・接点・負荷の場所（ページ、図面の幅と高さに対する位置、3×3 の言葉「左上・中央・右下」など）、
    a 接点・b 接点の数、タイマーの設定（DD-0033）、接点の枠に書かれたコイルのシート番号。
    場所はページの中で上から順に並べる。
  - **要確認**（判定はせず「どこを見ればよいか」だけを示す。矛盾の判定と直し方は検査タブの整合性チェック DD-0031 の役割）:
    - リレーなのに選んだ図面に接点が無い（ほかの図面にあるか、接点の器具番号の読み違い）
    - 同じ器具番号のコイルが 2 個以上（器具番号の重複か読み違い）
    - 表記の違うラベル（O と 0、I と 1、B と 8 の違い。DD-0009）を同じ器具にまとめた
    - 接点の枠に書かれたコイルのシートと、実際にコイルのあるページが違う（シート番号は枝番を除いて比べる。DD-0030 と同じ。
      コイルのページのシート番号が分からなければ比べない）
    - 外部入力の接点の枠に書かれたコイルのシートが選んだ図面にあるのに、コイルが見つからない（読み違いの可能性）
    - 器具番号の無い接点（どのリレーの接点か分からないため外部入力として扱っている）
  - **電線番号**: 番号（空白・大文字小文字の違いは同じ番号とみなす）ごとに、その番号の配線の本数と、配線がつなぐ記号
    （分岐点とラベルの無い通り抜けの点は除く）とページ。同じ番号の配線が別のノードにあれば印を付ける
    （詳しい照合は検査タブの電線番号の照合）。番号は数字の順に並べる。
  - **Excel**: 4 枚のシート（機器一覧／接点の場所／電線番号／要確認）。見出しの固定とオートフィルタ付き。
    OCR の文字が「=」で始まっても式にしない。
- API（`routers/circuit.py`）: `POST /api/circuit/devices`（JSON）、`GET /api/circuit/devices.xlsx?project_ids=1,2`（Excel）。
  図面セット（DD-0041）の `project_ids` をそのまま渡せば、セット単位の索引になる。
- 画面（回路検証のパネルに「機器」タブ。`DevicePanel.tsx`）:
  - 器具番号・電線番号・ページで探す（全角・半角、大文字・小文字、空白の違いを無視）。
  - 一覧の種類: 機器／電線番号／要確認。機器はリレー・外部入力・負荷の順に、コイルと接点の場所をボタンで並べる。
  - 場所のボタンを押すと、図面がそのページに切り替わり、その記号を中心に拡大して枠を点滅させる
    （`DrawingViewer` の `focus`）。図面がパネルの下にある狭い画面では、図面までスクロールする。
  - 「Excel」で 4 枚のシートを書き出す。
  - 一度に描く件数は 200 件まで（多い図面セットでも重くならないように。残りは検索で絞り込む）。

区画番号（図枠の 1〜8・A〜F）は図面ごとに違い、読み取りも無いため使わず、位置は 3×3 の目安で示す。

## 3. 確認

| 対象 | 方法 | 結果 |
|---|---|---|
| 相互参照 | pytest（`tests/test_device_index.py`）、自己保持の回路 | リレーのコイルのページ・位置、接点 2 個（上から順）、a / b の数、外部入力・負荷の分け方 |
| 要確認 | 接点の無いリレー、O と 0 の表記ゆれ、コイル 2 個、コイルのシートの食い違い、選んだシートにあるはずのコイルが無い、器具番号の無い接点 | それぞれの種類の要確認が出る |
| 電線番号 | 同じ番号の配線 2 本（同じノード）、空白の違う番号（別のノード） | 数字の順に並び、前者は印なし、後者は「別のノード」「書き方が違う」が出る |
| シートの比べ方 | 枝番つきの図面（ER21236-1）のコイルと、枠に ER21236 と書かれた接点。シート番号の無い図面 | どちらも食い違いにしない（セルフレビューで見つけて直した） |
| Excel | 4 枚のシートの名前、先頭の器具、「=1+1」の電線番号 | 式にならず文字のまま |
| API | JSON と Excel、不正な `project_ids`、無い図面 | 200 / 422 / 400 |
| 画面 | vitest（`DevicePanel.test.tsx`） | 場所を押すと図面の位置を渡す、全角の検索、要確認だけの表示、Excel の書き出し |
| 実画面 | 合成の展開接続図 3 枚（`analysis/synthetic_circuits/logic`、読み違い 2 か所を入れた）で回路を作り、機器タブを操作（Playwright） | 器具 20・電線番号 23・要確認 2。接点を押すと別ページへ切り替わって記号を中心に拡大し、枠が点滅する。画面は docs/screenshots/circuit-device-index.png |

## 4. 残り

- 図枠の区画番号（1〜8・A〜F）の読み取りができれば、位置を「3-C」のように図面の書き方で示す。
- リレーの型式ごとの接点数（例: 4a4b）が属性にあれば、使いすぎ・空き接点を示す。
- 端子台（TB）・コネクタ（CN）の端子番号ごとの接続表は、端子の名前の読み取りがそろってから足す。
