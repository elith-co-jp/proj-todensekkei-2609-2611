# DD-0039: 全図面の解析を裏のジョブにし、図面ごとに保存する

- 状態: レビュー中
- 作成日: 2026-11-21
- 関連文書: [DD-0012](DD-0012-speed-and-ci.md)、[DD-0019](DD-0019-card-model.md)

## 1. 目的

「AI 改善サイクル」の解析は、選んだ図面（未選択なら全図面）を 1 回の HTTP 要求の中で順に解析していた。

- 1 枚約 5 秒（2026-11-20 の計測）なので、顧客の 90 枚では 7〜8 分、画面は待つだけで進み具合が分からない。
- 途中の 1 枚が失敗すると全部を巻き戻し、それまでの図面の結果も保存されない。
- EXE はブラウザからの合図が 5 分途切れると自分で終わるので、解析中に画面を閉じると解析も止まる。

## 2. 変えたこと

- `services/analysis_jobs.py`: 解析のジョブ。裏のスレッドで 1 枚ずつ解析し、**図面ごとに保存**する。失敗した図面は理由とともに
  `failures` に入れて**次の図面へ進む**。中止すると、解析中の図面を終えたところで止まる（保存済みの図面はそのまま）。
  ジョブはプロセスの中だけに持つ（EXE・1 台のサーバの運用。再起動すると一覧は消えるが、保存した結果は残る）。
- `services/inference_service.run_inference`: `keep_going`（図面ごとに commit し、失敗を飛ばす）・`on_progress`・`should_stop` を足した。
  既定の動き（1 枚でも失敗すれば全部を保存しない）は、図面 1 枚の解析画面と既存の `POST /api/ml/analysis/run` のために残す。
- API（`routers/ml.py`）:

| メソッド | パス | 内容 |
|---|---|---|
| `POST` | `/api/ml/analysis/jobs` | `{project_ids[], conf, connector_conf}`（空なら全図面）。202 でジョブを返す。解析中なら 409 |
| `GET` | `/api/ml/analysis/jobs` | 最近のジョブ（新しい順、最大 20） |
| `GET` | `/api/ml/analysis/jobs/{id}` | `status`（running / done / cancelled / failed）、`done` / `total`、`current`（解析中の図面）、`results`、`failures` |
| `POST` | `/api/ml/analysis/jobs/{id}/cancel` | 解析中の図面を終えたら止める |

- 画面（AI 改善サイクル）: 「AI 解析を実行」でジョブを始め、1 秒ごとに進み具合（何枚目か・解析中の図面・失敗の数）と中止ボタンを出す。
  画面を離れて戻っても、解析中のジョブがあれば表示を続ける。終われば、保存した結果と、解析できなかった図面の名前を知らせる。
- EXE の自動終了（`main.py`）は、解析中のジョブがある間は待つ。

## 3. 確認

| 対象 | 方法 | 結果 |
|---|---|---|
| 失敗を飛ばす | 3 枚のうち 2 枚目の構造解析で例外 | 1・3 枚目は保存、2 枚目は failures に理由つき、状態 done、次のジョブを始められる |
| 中止 | 1 枚目の解析中に中止 | 1 枚目を終えて cancelled、done = 1。解析中に 2 つ目を始めると 409 |
| 画面 | vitest | 進み具合・解析中の図面・失敗の知らせ・中止ボタン |
