# DD-0033: タイマーと時間の流れ、入力の接点の名前、AI の読み取りの誤りへの対応

- 状態: レビュー中
- 作成日: 2026-11-18
- 関連文書: [DD-0032](DD-0032-synthetic-logic-validation.md), [DD-0031](DD-0031-consistency-check.md), [DD-0029](DD-0029-circuit-code-whatif-impact.md)
- 結果: [docs/evidence/DD-0033-logic-validation-timers-20261118.md](../evidence/DD-0033-logic-validation-timers-20261118.md)

## 1. 目的

DD-0032 の検証で残った課題のうち、効果の大きいものに対応する。

1. タイマー（限時継電器）と時間の順序。シーケンス図の「A を押して 5 秒後に B が動く」を再現できないと、もしもの検討が
   時間を含む回路で使えない。
2. 押しボタンなど入力の接点は、リレー表のような照合先が無く、a/b の読み違いを 1 件も見つけられなかった。
3. AI の読み取りで起きる、ラベルの読み落とし・コイルの見落とし・記号の二重の検出・誤検出を合成データに入れて測る。

## 2. タイマー

| 項目 | 内容 |
|------|------|
| 表し方 | リレーコイルの属性 `timer_mode`（on_delay / off_delay。オンディレー・オフディレー・限時動作・限時復帰も可）と `delay_s`（秒）。エディタの属性の定義に追加 |
| 接点 | タイマーの接点は限時接点（出力に従う）。属性 `timer_contact = instant`（瞬時）の接点はコイルに従う |
| オンディレー | 励磁が続いて delay_s で出力 ON。切れたらすぐ OFF |
| オフディレー | 励磁ですぐ ON。切れて delay_s で OFF（その間に励磁し直したら OFF にならない） |
| 時間が無い | `delay_s` が無いタイマーは 0 秒として扱い、確認が必要な箇所（timer_without_delay）に出す |

`services/circuit_timing.run_timeline(circuit, events, until=, change=, delays=)` は、操作の時刻とタイマーの満了の順に
進め、出来事ごとに回路を解き直す（`simulate(..., timer_outputs=)`）。タイマーの出力が変わったら同じ時刻でもう一度解く。
`change` は DD-0029 のもしも（断線・溶着など）、`delays` はタイマーの時間の変更（「5 秒を 8 秒にしたら」）。

- API: `POST /api/circuit/timeline` `{project_ids, events: [{at, inputs}], delays, until, change}` → 状態が変わった時刻ごとの
  記録（リレー・タイマーの出力と満了の予定・負荷・前からの変化）。`/build` は `timers` も返す。
- 画面: 回路シミュレーションの「時間の流れ（タイマー）」。操作の時刻、タイマーの時間の変更、時刻ごとの変化。
- 回路コード: `c.timer(器具番号, 'on_delay', 秒)`、接点の `instant=True`。書き出して読み戻してもタイマーが残る。

### 検証

正解は `logic.oracle_timeline`: 0.25 秒の一定の刻みで時間を進め、タイマーは励磁・無励磁の刻みを数える（出来事の順に
進める `run_timeline` と別の解き方）。合成回路のリレーの 35% をタイマー（0.5〜5 秒）にし、0.5 秒刻みの時刻で入力を
切り替える操作 3 通り × 25 秒で、刻みごとにリレー・タイマーの出力・表示灯を比べる。タイマーの時間を 1 秒ずらすと
正解とずれることも確かめた（比べ方が時間に敏感であること）。

## 3. 入力の接点の名前（`input_names`）

入力（コイルが無い器具）の名前が取り決めで種類の決まるもの（停止・非常停止・STOP・OFF・切 → b、起動・運転・START・
ON・入 → a）なら、接点の種類と比べる。停止用のリレーを動かす a 接点のように取り決めと違う使い方もあるので「要確認」に
し、直し方は付けるが、まとめて直す対象にはしない。「PB01」のように名前から決まらない入力は比べない。

I/O 表（入力の一覧）を照合先にする取り込みは、書式のサンプルを受け取ってから足す。

## 4. AI の読み取りの誤り

| 誤り | 見つけ方 |
|------|----------|
| 接点のラベルの読み落とし（空） | リレー表の行列の位置の接点のラベルが空 → 表の器具番号に直す。表がコイルの図面にあり、接点が別の図面なら、コイルのシート番号も付ける |
| コイルの見落とし | リレー表の器具のコイルが無い。場所としてその図面と、その器具の接点を示す |
| 記号の二重の検出 | 配線の無い記号が、同じ種類の記号とほぼ同じ位置に重なっている |
| 記号の誤検出 | どこにもつながっていない接点・コイル・負荷 |

## 5. 結果

[証跡](../evidence/DD-0033-logic-validation-timers-20261118.md)（60 回路、リレーの 35% をタイマー、誤り 2,811 件）。

- 時間の流れ: タイマー 152 個を含む回路で、刻みごとの状態 15,756/15,756 が正解と一致。誤りの無い図面での矛盾チェックの誤検出 0。
- 最初の測定で 1 回路（85 刻み）がずれた。タイマーの満了と同じ時刻に停止が押され、操作とタイマーのどちらを先に解くかで
  結果が分かれる「ぎりぎりの競合」だった。同じ時刻なら操作を先に解き、コイルの状態が続いているタイマーだけを満了させ、
  競合したことを記録の警告に出すようにした。
- ラベルの読み落とし: 検出・正しい直し方・正解への復帰 100%。コイルの見落とし・二重の検出・誤検出: 検出と場所 100%。
- 入力の接点の a/b: 46%（停止など名前から決まるものはすべて検出。「PB01」のように名前から決まらないものは I/O 表待ち）。
- 誤った直し方: どの種類も 0 件。

## 6. 残っていること

- I/O 表の取り込みと照合（書式のサンプル待ち）。
- タイマーの記号（限時接点の形）を AI が読み分けること。今はコイルの属性を人が入れる。
- 実図面（正解データ）でのチェックの誤検出の測定。
