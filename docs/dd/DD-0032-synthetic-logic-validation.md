# DD-0032: 正解つきの合成回路で、回路の理解・シミュレーション・矛盾チェックを検証する

- 状態: レビュー中
- 作成日: 2026-11-18
- 関連文書: [DD-0031](DD-0031-consistency-check.md), [DD-0030](DD-0030-sheet-links.md), [DD-0029](DD-0029-circuit-code-whatif-impact.md), [DD-0027](DD-0027-synthetic-circuit-loop.md)
- 結果: [docs/evidence/DD-0032-logic-validation-20261118.md](../evidence/DD-0032-logic-validation-20261118.md)

## 1. 目的

DD-0029〜0031 で、図面を回路として理解し（回路のコード）、動かし（もしも・手順）、波及範囲を出し、解析方法どうしの
矛盾を見つけて直せるようにした。これらが正しいかを、正解がわかっている回路で確かめる。実図面の正解データは画像と記号の
正解で、回路の動作の正解（論理）は無いため、論理から図面を作る合成データを使う。DD-0027 の合成は画像と配線の検出の
検証用で、1 枚ごとの単純な段だったので、回路の理解の検証用に別に作る。

## 2. 合成する回路（`analysis/synthetic_circuits/logic.py`）

回路の正本（`Spec`）を乱数の種から作り、図面（アノテーションと同じ形）・構造解析（リレー表・図面枠の行列）・母線の文字にする。

| 要素 | 内容 |
|------|------|
| シート | 2〜4 枚（ER21301…）。シートごとに P・N の母線と PER/NER の文字 |
| リレーの段 | 停止の b 接点、起動（押しボタンか前のリレーの a 接点）と自己保持の a 接点の並列、インターロック（前のリレーの a/b 接点） |
| 表示灯の段 | リレーの接点で点く。接点を使わないリレーには表示灯の段を足す（実図面と同じく、リレー表に必ず行がある） |
| 図面をまたぐ段 | 接点のシートから行先札「ER21302へ」、コイルのシートに来先札「(ER21301)」。両側の配線は同じ電線番号 |
| 接点のラベル | コイルが別のシートなら「33HE FV2304 (ER21302)」 |
| 電線番号 | つながりごとに 1 つ（行先札の両側も同じ） |
| リレー表 | コイルのシートに、接点ごとの行（器具番号・端子・a/b・シート「本」か番号・行列の位置） |

リレーは番号の若い順にしか前のリレーの接点を使わない（自己保持を除き、循環しない）。

## 3. 正解（oracle）

回路の電気の計算と独立に、段を論理式（直列 = かつ、並列 = または、a 接点 = 器具が ON、b 接点 = OFF）として解く。
前の励磁から、全リレーを同時に更新して状態が変わらなくなるまで（シミュレーションと同じ動作の定義）。波及範囲の正解は、
段の接点の器具 → 負荷の依存関係をたどった範囲。

## 4. 検証すること（`analysis/synthetic_circuits/logic_eval.py`）

1. 再現: 図面から組んだ回路の器具（リレー・入力）が正本とそろい、行先札をすべて組にする。
2. 動作: ランダムな入力・前の励磁 20 通りと、入力を 1 つずつ切り替える操作の手順 8 回で、シミュレーションと正解が一致する
   （リレーの励磁・表示灯）。回路のコード（DD-0029）に書き出して実行し直した回路も同じ。
3. 波及範囲: 器具ごとの静的な波及範囲（リレー・表示灯）が正解の依存関係と一致する。
4. 回路計算どうし: 内蔵の回路計算と Lcapy（と ngspice）で電圧の有無が一致する。
5. 矛盾チェック（DD-0031）:
   - 誤りの無い図面で指摘 0（誤検出）。
   - 誤りを 1 つ入れた図面で、見つけるか、場所（記号か行列の位置）を指すか、正しい直し方を出すか、直し方をすべて
     適用すると正解の動作に戻り矛盾が 0 になるか、誤った直し方（ほかの記号・元に戻らない値）を出さないか。

入れる誤りは、図面の読み取りで起きる種類にする: 接点の a/b、コイル・接点の器具番号の 1 文字、接点のシート番号、
接点の見落とし、配線の途切れ、電線番号の 1 文字、余分な接続（近くの段の端子どうし）、行先札のシート番号。
押しボタンなどの入力の接点（リレー表に行が無い）は別に数える。

実行: `python analysis/tools/validate_circuit_logic.py --seeds 60 --faults 3 --solvers 8 --out runs/logic_validation`
（約 3 分）。テスト: `tests/test_logic_validation.py`（3 回路で 2〜3 の誤りの種類、約 20 秒）。

回路計算どうし 8/8 回路（65 状態）、矛盾チェックの誤検出 0 件。

| 誤りの種類 | 検出 | 正しい直し方 → 正解に戻る | 誤った直し方 |
|------------|------|---------------------------|--------------|
| 接点の a/b | 100% | 100% | 0 |
| コイルの器具番号 | 100% | 100% | 0 |
| 接点の器具番号 | 100% | 100% | 0 |
| 接点のシート番号 | 100% | 100% | 0 |
| 行先札のシート番号 | 100% | 100% | 0 |

## 6. 検証で見つかり、直したこと（DD-0031 の規則）

最初の測定（6 回路）では、接点の a/b の検出 50%、コイルの器具番号の誤りで「接点のラベルを直す」誤った直し方 14 件、
配線の途切れの検出 0%、行先札の読み違いの検出 0%（回路の診断のみ）、誤りの無い図面で回路計算どうしの誤検出があった。

| 見つかったこと | 原因 | 直し方 |
|----------------|------|--------|
| コイルの器具番号の読み違いで、接点のラベルを直す提案 | 接点の指すシートの 1 文字違いのコイルに、接点を合わせていた | ほかの接点・リレー表の行が接点と同じ器具番号なら、コイルのラベルを直す（リレー表の直し方と一致して 1 つにまとまる） |
| 接点の器具番号の直し方が人の判断に回る | リレー表の直し方がシート番号「(ER…)」を落とし、シート番号の精査の直し方と値が違った | 器具番号だけを表の読みにし、シート番号は残す |
| 隣の列に同じリレーの接点があると a/b を直せない | 表の行を 1 行ずつ照合していた | 図面ごとに表の行をまとめて 1 行 1 接点で結び付け、ほかの接点が別の行に結び付いたなら 1 つに決まったとする |
| 接点の見落としを「器具番号が違う」と誤って指摘 | 窓の中の隣の接点（別の器具）を最も近い接点にしていた | 最も近い接点が別の器具（1 文字違いでもない）なら「位置に接点が無い」とし、位置と隣の接点を示す |
| 配線の途切れを見逃す | 配線 1 本のつながりは電線番号で比べられない | 新しい組「記号の端子 × 配線」: 2 端子の片方だけ配線がある記号を指摘 |
| 行先札の読み違いが矛盾チェックに出ない | 組にならない札は回路の診断だけだった | 組にならない札に、同じ電線番号でこちらへ向かう札がほかの図面に 1 つあれば、札のラベルの直し方を出す |
| 接点のシート番号の読み違いを直せない | 精査の結論が「確かめる」だけ | 同じ器具番号のコイルがほかの 1 枚だけにあれば、シート番号を直す |
| 余分な接続で「a 接点にする」と提案 | 発振を a/b の読み違いと決めていた | リレー表でも b 接点なら直し方を出さず、余分な接続を疑う |
| 誤りの無い図面で回路計算どうしが食い違う | 開いた接点の間で浮いたノードを、内蔵は分圧（55 V）、Lcapy は 0 V と解く | 電源の 9 割以上を「あり」、1 割以下を「なし」とし、その間（浮いたノード）は比べない |

## 7. 残っていること・限界

- 押しボタン・リミットスイッチなどの入力の接点は、リレー表のような第 2 の根拠が無いため、a/b・器具番号の読み違いを
  見つけられない。入出力の一覧（I/O 表）や、停止 = b 接点のような取り決めを根拠に足すかを決める。
- 合成の回路は規則的（段の形・座標・ラベルの書式）。実図面（正解データの 30 図面）でもチェックを流して誤検出を測る（DD-0031 §6）。
- タイマー・時間の順序、コネクタのピンでの図面間のつながりは合成にも入れていない（DD-0029 §7）。
