# DD-0035: 展開接続図を読む手順の機械化と、正解のやり取り・正解率の測り方

- 状態: レビュー中

## 1. 目的

2026-11-18 の東電設計様との会議（画面共有）で、展開接続図を人が読む手順が説明された。

1. 問いを置き、対象を一点に決める（起動条件を知るなら結果から逆に、故障の影響を知るなら変化した要素から順に）。
2. 記号を読み、参照先（別シート・リレー表）を照合する。
3. コイルだけでなく、電源側から戻り側までの経路を見る（コイルより下の接点も条件）。
4. 直列は AND、並列は OR。枝の一部だけ成立しても通電としない。
5. 接点を動かす元へ繰り返し辿る。I/O・上位からの指令は図面範囲の外部入力。参照先が読めない・無いものは「未解決」。
6. 成立した条件を順方向でつなぎ直す。

あわせて、正解データ（アノテーション）のやり取りの形（対応表の Excel、代表回路の正解、CVAT）と、文字・記号・線・参照・
代表回路を分けて測る正解率が提案された。本 DD はこれらをシステムに入れる。これまでの「もしも」（DD-0029）は回路計算で
状態を解くだけで、条件の構造（直列・並列）と「判定不能」を返せなかった。また波及範囲は「同じ段にあるか」だけだった。

## 2. 成立条件の逆引き（`services/circuit_trace.py`）

- **枝（経路）**: 対象の負荷（コイル・表示灯など）の両端から、接点だけを通って電源（P）と戻り（0）に着く単純な経路を
  全部列挙し、組み合わせる。他の負荷は通らない。母線は終点にしかならない。1 つの負荷で 256 本を上限とし、超えたら
  `truncated` を付ける。各接点には「電源側」「戻り側」を付ける（戻り側の接点も条件に入る）。
- **成立条件**: 枝ごとの接点の AND を OR でまとめ、吸収（ある枝を含む枝を除く）と共通の接点のくくり出しで式の木にする。
  a 接点は器具の動作で導通、b 接点は `¬`。例: `A ∧ D ∧ (B ∨ C)`。同じ器具の a と b が直列の枝はどの状態でも導通しない
  ので式から外し、判定の理由に「読み違いの可能性」として出す。
- **式の文字列**: 表示は `∧ ∨ ¬`、読み戻せる形は `& | !`（空白を含む器具番号は `"..."`）。`parse` は
  `AND / OR / NOT`、`∧ ∨ ¬`、`「...」` も読む。`equivalent` は変数 16 個まで全通り、それより多ければ 4096 組で比べる。

## 3. 器具の出どころ（接点を動かす元）

| 出どころ | 条件 | 判定での扱い |
|---|---|---|
| リレー | 同じ器具番号のコイルが図面セットにある | そのコイルの成立条件を同じ手順で求める（繰り返し辿る） |
| 外部入力 | 接点の属性 `external_io` が真、I/O 表で指定（`external`）、またはコイルも参照の記載も無い | 状態を与えなければ「不明」 |
| 参照先欠落 | 接点のラベルの参照シート（例「(ER21302)」）が図面セットに無い | 「不明」。参照先を求める |
| 未解決 | 参照先のシートはあるがそのコイルが無い、器具番号が読めない | 「不明」 |

これまでの回路（DD-0009）はコイルの無い接点をすべて外部入力にしていた。本 DD で「参照先欠落」「未解決」を分ける。
接点の属性に `external_io`（外部入力・I/O）を足した。

## 4. 3 値の判定

`Tracer.evaluate(対象, states, energized)`。states は器具番号 → 動作（true）/ 非動作（false）/ 不明（null）。

- 器具の値: 与えた値、なければリレーは条件から導く（Kleene の 3 値論理）。外部入力・参照先欠落・未解決は不明。
- 自己保持: 辿っている途中のリレーに戻ったら、前の状態（energized）を使う。無ければ不明。
- 枝: 接点のどれかが開なら「不成立」（どの接点で切れたか）、全部導通なら「成立」、ほかは「判定不能」（どれが不明か）。
- 対象: どれかの枝が成立なら「成立」、全部不成立なら「不成立」、ほかは「判定不能」。
- 経路が 1 本も無いときは「判定不能」（配線の読み取り漏れ・薄い線の可能性。原本を確認）。
- 対象から接点でたどれるところに行先の分からない札（DD-0030 の `sheet_link_unresolved`）があれば、その先に別の枝が
  ありうるので「不成立」と断定せず「判定不能」にする。
- 結果の各接点に、ページ名・記号・中心の座標・電源側／戻り側・器具の状態とその決め方を付ける。

`explain` は条件に出てくるリレーを、外部入力・参照先欠落・未解決に着くまで辿った木を返す（手順 5）。

## 5. 順引き（影響確認）

`Tracer.effects(器具)`。その器具の接点を条件に含む負荷を段数つきで返し、全部の枝にある（必須: 単独で成立を左右する）か、
一部の枝だけ（ほかの枝しだい）かを付ける。states を与えると、器具を反転したときの各負荷の判定の変化（成立 → 不成立 など）
も返す。DD-0029 の波及範囲（段で区切る）より細かく、同じ段でも経路に乗らない接点は含めない。

## 6. 代表回路の正解（`services/circuit_scenarios.py`）

会議資料の「代表回路の正解」（何を知りたいか・起点／出力・追う順番とページ・成立条件・成立しない例）を 1 件ずつの
シナリオ（YAML / JSON、または対応表の「代表回路」シート）で書く。照合するのは、対象が見つかるか、成立条件が同じ論理か
（反例を返す）、例ごとの判定、順引きの影響先の適合率・再現率、根拠のページが正解のページを含むか。名前は器具番号の
全体・先頭の語（一意なとき）で回路の器具に当てる。

## 7. 正解のやり取り

### 7.1 対応表（`services/annotation_table.py`）

列は会議資料の提案どおり「図面セットID／ページID／要素ID／種別／原文／参照・接続先ID／判定／根拠・備考」。要素 ID は
「ページ:記号 ref」、端子は「ページ:記号 ref/端子名」。行は記号 1 個、配線 1 本、行先札の組 1 組、コイルと接点の対応
1 組（コイルの無い接点は出どころ）。2 枚目のシート「代表回路」は記入例つき。Elith が書き出して送り、東電設計様が判定の列
（接続／非接続／不明）や原文を直して返す。返ってきた表は関係（配線・別ページの継続・コイルと接点の対応）ごとに適合率・
再現率と誤結線（正解で非接続の組を機械が出した数）、原文の完全一致率で照合する。「不明」の組は数えない。

### 7.2 CVAT（`services/cvat_format.py`）

CVAT for images 1.1 の XML。記号は box（属性 ref・text）、端子は points（group_id で記号に結ぶ）、配線は polyline
（属性 from・to・wire_no・judge）。取り込みは端点をいちばん近い端子（12 px 以内）に着け、`judge=非接続` の線（単なる交差
の例）は配線にしない。画像名の `p{図面 ID}_` か図面名・シート番号で図面に当て、大きさが違えば警告する。まず確認だけ
（apply=false）、適用すると図面のアノテーションを置き換える。ページをまたぐ関係は CVAT に入れず対応表で扱う。

## 8. ベクター PDF からの線・文字（`services/vector_pdf.py`）

PDF で図面を登録すると、ページごとに PyMuPDF で線・塗りつぶした小さい図形（黒丸）・文字を取り出し、画像と同じ座標
（150 dpi、登録時に横書きの図面を回したなら同じだけ回す）で `DATA_DIR/vector_pdf/{図面 ID}.json` に保存する。
`GET /api/projects/{id}/vector-pdf` で返す。

- ページ幅（高さ）の 85% 以上の線、ページの端に沿う長い線は図枠として外す。破線は盤の枠・注釈線として別に返す。
- 細切れの同じ線はつなぐ。端点の一致・T 字は接続。十字の交わりは交点に黒丸があるときだけ接続し、無ければ単なる交差
  （`crossings`）として返す。接続でまとめた線の集まりを `nets` で返す（電気的な接続の候補。正本はアノテーション）。
- 文字は行ごとに外接枠・向き（横・縦・回転）・大きさ。構造解析の文字が無い図面では、母線の PER/NER の判定にこの文字を
  使う。画像だけの PDF（スキャン）は `kind = "scan"`。

## 9. 正解率を分けて測る（`services/reading_metrics.py`・`analysis/tools/eval_reading.py`）

正解と機械の結果（どちらも書き出し ZIP か bundle.json）をページ（シート番号）で対応づけて測る。

| 項目 | 測り方 |
|---|---|
| 記号 | 種類別の適合率・再現率（IoU ≥ 0.5 で当て、種類も同じなら正解） |
| 文字 | 原文（ラベル）・器具番号（先頭の語）・端子番号の完全一致（全角半角・空白は無視） |
| 線 | 端子の組の適合率・再現率。正解で別のネットの組は「誤結線」、同じネットなら「経路違い」 |
| 別ページの参照 | 行先札の組の一致 |
| コイルと接点の対応 | 接点 → コイルの組の一致、コイルの無い接点の出どころの一致 |
| 代表回路 | シナリオの合格数（機械の図面と正解の図面の両方で） |
| 人の修正量 | 記号の追加・削除・種類の変更、ラベルの書き直し、配線の追加・削除の数 |

図面セット（YAML でセット → ページ）ごとにまとめ、学習に使ったページの一覧を渡すと、評価に使うセットのページが学習に
混じっていないかを出す（同じ図面・設備の似たページを学習と評価に分けない）。

## 10. API と画面

| API | 内容 |
|---|---|
| `POST /api/circuit/trace` | 逆引き（target / symbol、states、energized、external）か順引き（mode=forward、device） |
| `POST /api/circuit/trace/targets` | 対象（コイル・負荷）と起点（器具と出どころ）の一覧 |
| `GET /api/exchange/table` | 対応表（xlsx / csv / json） |
| `POST /api/exchange/table/compare` | 直された対応表（と代表回路のシート）の照合 |
| `POST /api/exchange/scenarios/evaluate` | 代表回路のシナリオの照合 |
| `GET /api/exchange/cvat`・`POST /api/exchange/cvat/import` | CVAT の書き出し・取り込み |
| `GET /api/projects/{id}/vector-pdf` | ベクター PDF の線・文字・接続の候補 |

回路シミュレーションの画面に「図面を読む手順（逆引き・順引き）」のパネルを足した。対象を選んで成立条件・判定・枝ごとの
接点（開は赤・不明は黄。押すとエディタのその記号へ）・辿った木を示し、順引きでは影響先と状態の変化を示す。入力の状態は
動作・非動作・不明から選ぶ。対応表と CVAT もここから書き出せる。

## 11. 検証

（[結果](../evidence/DD-0035-reading-procedure-20261120.md)）。

- シートを 1 枚抜いたとき（参照先欠落・行先の無い札）、断定した判定の誤り: 0 件（判定不能 1690）
